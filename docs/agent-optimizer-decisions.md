## 4. 大纲中的设计建议

| 编号 | 建议 | 为什么采用；如何改变 |
| --- | --- | --- |
| P1 | 采用本地模块化程序和薄工具入口，以文件记录为首版持久化方式 | 适合 C1、C2；接口保持可供未来独立研究程序调用，避免初期分布式服务复杂度 |
| P2 | 给定研究目标、可改范围与预算后，研究 Agent 自主完成候选实现、实验、分析与归档 | 延续用户的交付自治原则；改变目标、数据用途或真实执行范围时回到相应决定节点，不要求每轮常规实验人工确认 |
| P3 | 稳定协议和数值工具由程序维护，在线 LLM 先选择、组合与纠错已验证能力 | 便于公平对照和失败回退；是否扩大到在线新代码按实验决定 |
| P4 | 扩样同时包含同类新样本和不同场景条件，开发与冻结评价按任务家族分组 | 降低近重复样本和单一生成分布的影响；具体维度、数量与配比在数据节点验证 |
| P5 | 研究工作区、数据与评价程序、可交付在线项目之间建立边界 | 避免模型读未来、候选改评分和比赛项目依赖开发环境；物理隔离方式在实施时选择 |

P1–P5 尚未经独立评审。用户后来同意方案并授权数据构建；真实调用和线上执行仍按受控试用路由处理，不能从数据构建授权推导。
